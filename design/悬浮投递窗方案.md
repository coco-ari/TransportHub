# TransportHub 悬浮投递窗设计方案（确认稿候选）

> 本文只定义产品和交互，不代表正式程序已经开发完成。配套原型不会复制或同步真实文件。

## 1. 产品定位

TransportHub 悬浮投递窗是 Syncthing 上方的一层轻量 Windows 界面。它只负责让“发送资料”变得像把文件丢进聊天窗口一样简单；设备发现、断点续传、加密、局域网直连和公网中继仍由 Syncthing 完成。

核心原则：

- 默认发送到所有已共享 `transporthub-data` 的电脑，不要求每次选择接收者。
- 文件先进入本机投递目录，再由 Syncthing 同步。
- 界面明确区分“已投递到本机”和“其他电脑已同步”，不虚报传输成功。
- 视频在第一版中作为普通视频文件发送；不包含实时音视频通话。

## 2. 第一版功能范围

### 日常发送

- 把文件或文件夹拖到悬浮窗即可投递。
- 提供“选择文件”“选择文件夹”按钮，兼容不习惯拖拽的操作方式。
- 支持粘贴或输入文字；每条文字作为独立消息文件同步，其他电脑自动显示为消息气泡。详细协议见《文字消息同步方案》。
- 窗口位于前台时，粘贴微信图片、截图或本地图片会立即生成图片卡并投递；粘贴单独的 HTTP/HTTPS 网址会立即生成链接卡。
- 文件重名时自动生成安全的新名称，不静默覆盖。
- 大文件在后台复制，显示进度，可取消，不阻塞窗口。

### 桌面窗口

- 默认置顶，可拖动到任意显示器。
- 可折叠为屏幕边缘按钮，点击恢复；文件仍可直接拖到按钮投递。
- 关闭按钮默认隐藏到系统托盘，不退出同步服务。
- 记住上次显示器、边缘位置和展开/折叠状态。

### 状态和记录

- 顶部显示在线设备数量，例如“3 台在线，1 台离线”。
- 最近动态同时显示本机发送和其他电脑发来的资料。
- 单击文字气泡复制完整正文；用户正在拖动选择局部文字时不触发整条复制。
- 单击文件记录：打开资源管理器并选中文件。
- 不默认双击执行文件，尤其不自动运行 `.exe`、`.bat`、`.ps1` 等程序。
- 新资料到达时可显示 Windows 通知；点击通知在资源管理器中定位。

## 3. 状态语义

| 界面状态 | 准确含义 | 用户应该怎么理解 |
|---|---|---|
| 正在复制 68% | 文件仍在复制到本机投递目录 | 还没有正式交给 Syncthing |
| 已投递 · 同步中 | 本机文件已经完整落盘，Syncthing 正在处理 | 可以关闭投递窗，后台会继续 |
| 全部设备已同步 | 所有目标设备当前在线，且共享文件夹已达到最新状态 | 可视为本轮同步完成 |
| 等待 1 台设备上线 | 在线设备已同步，仍有离线目标 | 离线电脑上线后自动补齐 |
| 同步服务离线 | Syncthing 没有运行或接口不可用 | 仍可保存到本机；服务恢复后再同步 |

“全部设备已同步”来自 Syncthing 的设备/文件夹完成状态。第一版不会声称能提供严格的逐文件送达回执；界面会在说明中保持这一边界。

## 4. 窗口结构

最终确认候选采用一个统一时间线，不再把文字和文件拆成两个页面。文字显示为消息气泡，文件和文件夹显示为同一时间线中的卡片，统一按时间排序。

当前高密度展开尺寸为 `330 × 480` 逻辑像素；标题栏约 `46`、发送框约 `54`，其余空间全部留给时间线。折叠后是约 `40 × 40` 的屏幕边缘按钮。尺寸属于实现细节，后续可随可用性测试继续调整。

发送框保持极简，只包含附件图标、消息输入区和发送箭头。附件使用回形针图标，不使用“＋”或“选择文件”文字；不常驻显示快捷键、粘贴说明和“发送到全部电脑”等辅助文案，这些能力通过 tooltip、首次引导和设置页说明。

```text
┌──────────────────────────────────┐
│ TransportHub   ● 3台在线   📌 ︿ × │
├──────────────────────────────────┤
│ 消息与文件             3在线 / 4台 │
│                                  │
│ PC-OFFICE：资料已经整理好了。      │
│ ┌────────────────────────────┐   │
│ │ XLSX  客户反馈汇总.xlsx     │   │
│ └────────────────────────────┘   │
│                    收到，谢谢。   │
│                       已送达 2/3  │
├──────────────────────────────────┤
│ ＋  输入消息……             [发送] │
├──────────────────────────────────┤
│ Syncthing 已连接      打开同步目录 │
└──────────────────────────────────┘
```

## 5. 关键交互

### 拖入文件

1. 指针进入窗口后，整个投递区高亮并显示“松开发送到全部电脑”。
2. 松开后先检查文件名、目标空间、目录联接和重名。
3. 后台复制时出现进度卡片。
4. 本机完整落盘后状态变为“已投递 · 同步中”。
5. Syncthing 状态更新后显示“全部已同步”或“等待设备上线”。

### 发送文字和复制

1. 输入文字后按 `Enter` 或点击发送；`Shift + Enter` 换行。
2. 其他安装了投递窗的电脑在统一时间线中自动显示气泡；离线电脑上线后补收。
3. 单击气泡复制完整正文并显示短暂的“已复制”；拖动选中文字时只保留正常的局部复制行为。
4. 显示“已送达几台电脑”；送达只代表投递窗已接收，不代表人工已读。
5. 底层采用“每条消息一个不可变 JSON 文件”，避免多台电脑同时修改同一聊天记录造成 Syncthing 冲突。

### 主动粘贴

只有完整窗口在前台，且用户主动按 `Ctrl + V` 或执行“粘贴”时才读取一次剪贴板，不后台监听。

处理顺序：

1. 本地文件列表：直接进入文件投递，永远执行复制，不移动源文件。
2. PNG、Bitmap、DIB 等真实图片数据：立即保存为独立图片，加入时间线并同步；微信图片和 Windows 截图走这条路径。
3. 单独一个 `http://` 或 `https://` 网址：立即发送网址卡片，不在后台自动下载远程资源。
4. 其他普通文字：只粘贴到输入框，等待用户发送，避免误发普通剪贴板文本。

折叠按钮不注册全局粘贴热键；需要粘贴时先点击按钮恢复窗口。图片粘贴立即发送可在更多菜单中关闭，但按本方案默认开启。

### 折叠、置顶与退出

- 展开窗和折叠按钮默认保持在普通应用窗口上层，不使用定时器持续抢占焦点。
- 点击折叠按钮后，窗口变成当前显示器左侧或右侧边缘的悬浮按钮。
- 悬浮按钮显示应用图标、新消息徽标和同步状态点；单击恢复完整窗口并聚焦消息输入框。
- 文件或文件夹可以直接拖到悬浮按钮投递，不要求先展开窗口。
- 折叠位置按显示器、边缘和纵向比例保存；更换显示器、分辨率或 DPI 后自动夹回可见工作区。
- Windows 锁屏、UAC 安全桌面、`Ctrl+Alt+Delete` 和部分独占全屏游戏可能覆盖普通置顶窗口，这些系统边界不承诺持续显示。
- 点击关闭只隐藏到托盘；托盘菜单提供“显示窗口”“打开同步目录”“退出投递窗”。
- 退出投递窗不会退出 Syncthing，文件同步仍在后台继续。

## 6. 数据和安全边界

- 默认投递目录沿用现有规则：`%USERPROFILE%\TransportHub\<本机电脑名>`。
- 文件复制未完成前使用本地临时状态，完成后再以最终名称交给同步目录，尽量避免同步半成品。
- 拒绝目录联接、循环符号链接和越过同步根目录的路径。
- 最近记录只保存必要的本机元数据；“移除记录”不能删除实际文件。
- 真正删除同步目录中的文件会传播到其他电脑，界面必须二次确认并明确提示。
- 不读取或复制 Syncthing 的设备私钥，不把管理界面暴露到局域网或公网。
- 图片只在用户主动粘贴时读取；原型和正式程序都不轮询、不记录后台剪贴板。
- 网址卡只同步网址文本，不携带浏览器 Cookie、登录状态，也不自动发起下载或跟踪请求。
- 时间线只保存受控的相对路径；单击文件时由本机重新校验路径位于 TransportHub 根目录，再让资源管理器选中。

## 7. 暂不纳入第一版

- 实时视频通话、屏幕共享。
- 微信式多人聊天、表情、语音、已读回执。
- 手机端。
- 远程控制电脑。
- 替换 Syncthing 的发现、加密、NAT 穿透或中继能力。
- 在窗口中完成复杂的设备配对；第一版只显示设备状态并提供“打开配对页面”。

## 8. 需要确认的产品决策

请在看完原型后确认以下四项：

1. 默认是否始终发送到“全部电脑”，不增加每次选择接收设备的步骤。
2. 消息和文件是否按时间混排在同一个窗口，不再设计两个独立页面。
3. 单击文件记录是在资源管理器中选中文件，而不是直接打开或执行文件。
4. 文字使用独立消息文件同步，并在所有安装投递窗的电脑上显示为聊天气泡；不承诺未安装投递窗时提供聊天界面。
5. 窗口默认置顶；折叠后变成屏幕边缘按钮，单击恢复，拖文件到按钮也能投递。
6. 单击文字复制全文；粘贴真实图片或单独网址时立即发送，普通文字只进入输入框。
